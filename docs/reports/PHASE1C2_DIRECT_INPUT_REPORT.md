## 3. 8項目の対応

### 1. 女性NPCも「ぼく」と話す問題

**原因**: 台本が80人共通のテンプレート1本しかなく、一人称が直書きされていた。

**対応**:
- 名簿の年代と表示分類から一人称を引く `firstPerson()` を `src/data/avatars.ts` に追加。
- 台本側は `{npcI}` / `{meI}` と書き、`chatPanel` が名前（`{npc}` / `{me}`）と同じ仕組みで解決。
- 80人分の個別台本は作らず、台本は6本のまま維持。個別台本へ差し替えるときは
  `src/data/dialogues/index.ts` の `pickScript()` に `speakerAvatarId` ごとの台本を足せばよい。

**一人称の対応表**:

| 年代 | 男性(m) | 女性(f) |
|---|---|---|
| 小学生 | ぼく | わたし |
| 中学生 | ぼく | わたし |
| 高校生 | ぼく | わたし |
| 大学生 | ぼく | わたし |
| 大人 | わたし | わたし |

**確認**: 実機相当のブラウザで女性NPCが「わたしは絵里。」、男性NPCが「ぼくは真人。」と話すことを確認。
単体テストで「80人全員に一人称がある」「女性は『ぼく』と話さない」「年代と表示分類だけで決まる」
「乱暴に聞こえる言い方は使わない」「台本に一人称を直接書かない」を固定。

### 2. 英単語入力の大文字・小文字、前後空白の扱い

`normalizeEnglishAnswer()` で次を行い、**正解として扱う**。

- NFKC 正規化（`ａｐｐｌｅ` → `apple`）
- 前後の空白を落とす
- 語中の連続した空白を1つにまとめる（全角スペースを含む）
- 小文字へそろえる

iPhone の自動大文字化で `Apple` になっても正解。入力欄側でも `autocapitalize="off"` を設定し、
そもそも大文字化させないようにしています。

### 3. ひらがなの表記揺れをどこまで正解にするか

`normalizeJapaneseAnswer()` で次を行う。

**正解にする（入力方法の都合）**:
- NFKC 正規化（半角カタカナ `ﾘﾝｺﾞ` → `リンゴ`）
- カタカナ → ひらがな（`リンゴ` → `りんご`）
- 空白をすべて落とす

**区別する（語そのものの一部）**:
- 濁点・半濁点（`りんこ` は `りんご` の正解にしない）
- 促音（`がこう` は `がっこう` の正解にしない）
- 長音（`けき` は `けーき` の正解にしない）

意味が変わる例として `おばさん` / `おばあさん` を別物として扱うことをテストで固定しています。

判定は正解／不正解の2値。「おしい」表示は出しますが、内部的には不正解として記録し、
その場で正しい答えを見せて覚え直せるようにしました。

### 4. iPhoneで日本語・英語キーボードを切り替えた際の操作性

iOS はページ側からキーボードの入力言語を切り替えられないため、
**切り替えが必要な場面をそもそも作らない**方針にしました。

- 1回のテストの出題方向を `seed` から決めて全問で固定（`quizFormatForSeed()`）。
  テストの途中で「英語を打つ問題」と「ひらがなを打つ問題」が入れ替わらない。
- テスト開始前の案内画面で「えいごを じぶんで 入力します。」か
  「ひらがなを じぶんで 入力します。」を先に見せる。
- 入力欄の上に「えいごで入力」「ひらがなで入力」のラベルを常時表示。
- 入力欄に `lang` / `inputmode` / `autocapitalize` / `autocorrect` / `autocomplete` /
  `spellcheck` を答える言語に合わせて設定。
- 入力された文字種が答える言語と食い違うときは
  「えいごのキーボードに切りかえてね」等を案内。**採点には一切影響しない**
  （ローマ字入力の変換途中でかなと英字が混ざる場合は案内を出さない）。

### 5. Enter／完了／次へボタンの挙動

- 入力欄を `<form>` で囲み、送信で回答確定。iOS のキーボード右下のキーでそのまま答えられる。
- `enterkeyhint` は最終問題だけ `done`、それ以外は `next`。
- 画面上にも「こたえる」ボタンを置く（キーボードのキーに気づかない人向け）。
- 回答後は正誤を表示し、**自動では送らず**「つぎへ」で進む。
  不正解のときは正解を読む時間が要るため。
- 「つぎへ」は正誤表示の**下**に置き、結果を読んでから押す並びにした。
- 回答後は「こたえる」と入力中の案内を引っ込め、押せるボタンを1つだけにする。

### 6. 未入力、誤入力、連打への対策

- **未入力**: 入力が空のあいだ「こたえる」を無効化。`<form>` 送信でも進まない。
  「ことばを入力してね」とだけ出し、責める文言は出さない。
- **連打**: 採点に入ったらロックフラグを立て、正誤表示が終わるまで追加の送信を受け付けない。
  Phase 0 のカルタ（`PlaySession`）と同じ方式。表示回帰テストで
  「連打しても問題が飛ばない」ことを確認。
- **誤入力**: 入力欄の右端にクリアボタン（×）を置き、1タップで消せる。
- **回答回数**: 1問1回。不正解ならその場で正解を見せ、`incorrectPairIds` に入れて復習対象にする。
- **スキップ**: 案内画面とテスト中の両方から可能。`status: 'skipped'` として記録し、
  不正解としては数えない。学習記録も失われない。

### 7. 回答中に正解が見えてしまわない設計

**問題**: 結果画面の「覚えたことば」一覧に「つき moon」のように日本語と英語が並ぶ。
従来は「カルタ → 結果画面 → 確認テスト」の順だったため、答えを見てからテストを受けられた。

**対応**:
- 導線を **カルタ → ウェーブ終了チャット → 確認テスト → 結果・分析** へ入れ替えた。
- テスト画面は全画面で、カルタ盤面も結果一覧も見えない。
- 出題文に答えを含めない（`prompt` と `answer` を別フィールドにし、テストで固定）。
- 表示回帰テストで「テスト画面に正解の文字列が存在しない」ことを3サイズで確認。

### 8. 320×568でも入力欄がキーボードに隠れないこと

- テスト画面だけ下部固定レイアウトをやめ、
  上から「進捗 → 出題 → 入力欄 → こたえる」の縦並びにした。
- 本文を `overflow-y: auto` にし、`visualViewport` の `resize` で
  キーボードの高さを測って入力欄を可視領域へ寄せる。
- 画面が低いとき（`max-height: 460px`）は、見出しと「今回はスキップ」を畳み、
  出題カードの余白と文字を圧縮して、入力欄と「こたえる」を必ず残す。
- 入力欄の文字サイズは 20px（狭い画面で 18px）。16px 未満だと iOS が入力時に画面を拡大するため。

**確認**: キーボードが出ている状態をビューポートの高さを縮めて再現し
（320×300 / 393×420）、出題・入力欄・「こたえる」がすべて可視で
44px 以上あり、横スクロールが出ないことを自動テストで確認。

> この項目は最初の実装でテストが実際に落ち（320×300 で「こたえる」が隠れた）、
> 短い画面用のレイアウト圧縮を入れて通るようにしました。
