直したこと
----------
コース選択と枚数選択のボタンで、aria-pressed（押されているかどうかを
読み上げへ伝える属性）が正しい値になっていなかった。

  src/screens/courseScreens.ts:78   コース選択の option-chip
  src/screens/courseScreens.ts:124  枚数選択の option-card--count

原因は、画面を組み立てる el() の書き出し方。
値が true のときは空文字を書き、false のときは属性ごと落とす。
disabled や hidden はそれで正しいが、aria-pressed では
「押されている／いない」が読み上げにまったく伝わらない。

どちらも String(...) で "true" / "false" の文字列にして渡すよう直した。
見た目を決める is-selected と同じ式から作っているので、
見た目と読み上げがずれることはない。

世界マップの印（worldMapScreen.ts）の同じ問題は、ひとつ前の工程で
直してある。

再発を防ぐ検査（src/tests/ariaState.test.ts・5件）
--------------------------------------------------
画面と部品のコードを読み、次を確かめる。

・状態を表す属性（aria-pressed / aria-selected / aria-checked /
  aria-expanded / aria-hidden）へ、真偽値をそのまま渡していない
  （文字列・String(...)・条件で 'true' を選ぶ書き方のみ可）
・コース選択・枚数選択・世界マップの印で、選択状態の属性が
  見た目（is-selected）と同じ条件から作られている
・世界マップは画面を作り直さずに選択が変わるため、
  押したときに属性も書き換えている
・el() が真偽値をどう書き出すか、という前提そのものの記録

String(...) を外して検査を走らせ、
「真偽値をそのまま渡している箇所：courseScreens.ts の aria-pressed」で
失敗することを確かめてある。
