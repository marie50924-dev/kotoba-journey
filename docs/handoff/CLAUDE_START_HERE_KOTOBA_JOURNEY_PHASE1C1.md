## 1. 今回の結論

今回ただちに実装するのは **Phase 1-C1だけ** です。

- 80人の正式データ
- 初回キャラクター選択
- 設定からの変更
- NPC選出・登場管理
- 安全な台本式チャットUI
- 保存データ移行
- テストと3サイズ表示確認

次は決定済みですが、今回のコミットへ実装してはいけません。

- ウェーブ後のアルファベット・ひらがな直接入力テスト
- 神経衰弱、スライド・スタック、スピード・トランプ
- SNS共有
- 非同期・ターン制・リアルタイム対戦
- 自由文AIチャット
- 課金

## 5. 実装対象A：80人の正式データ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

`kotoba-journey-character-names-v1.json` を正本として、アプリ内へ80人を登録してください。

既存構成に合わせ、単一のデータ源になる実装を選んでください。JSONとTypeScriptへ手作業で二重登録してはいけません。Vite/TypeScriptでJSON importを使う、または生成スクリプトを置くなど、再現可能な方法にしてください。

最低限の型：

```ts
type AvatarAgeGroup =
  | 'elementary'
  | 'middle'
  | 'high'
  | 'university'
  | 'adult';

type AvatarPresentation = 'm' | 'f';

interface AvatarDefinition {
  id: string;
  ageGroup: AvatarAgeGroup;
  presentation: AvatarPresentation;
  order: number;
  familyName: string;
  givenName: string;
  familyNameKana: string;
  givenNameKana: string;
  romanizedName: string;
  imageKey: string | null;
  enabled: boolean;
}
```

要件：

- 全80件
- 各年代16件
- 各年代で `m` 8件・`f` 8件
- ID、姓名が一意
- すべての正式名・かな・ローマ字が空でない
- 表示順がコンセプトシートと一致
- 画像未納品でもデータ登録は完了させる

- 大きな確認表示と「このキャラクターで旅する」

- 全操作44×44 CSS px以上
- 320×568で横スクロール0
- safe-area対応
- キャラクター年代と学習コースは独立

## 8. 実装対象D：NPC選出
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

自分が選んだ1人をNPC候補から除外し、残り79人が長期的に登場できる仕組みを作ってください。

`domain/` にDOM非依存の純粋関数として実装してください。

```ts
interface CastContext {
  screen: 'course' | 'map' | 'arrival' | 'wave-start' | 'wave-end' | 'result' | 'passport';
  selectedAvatarId: string;
  recentAvatarIds: string[];
  countryId?: string;
  courseId?: string;
  seed: number;
}
```

要件：

- 自分のキャラクターを選出しない
- 同一人物の連続登場を抑制
- seed指定で再現可能
- 候補不足でも例外を投げない
- 1画面に全79人を出さない
- 初期版は画面ごとに1～3人
- 年代や性別を理由に学習内容を制限しない

すべての画面へ一度に無理に組み込まず、Phase 1-C1では最低限、コース入口、世界地図または国到着、ウェーブ終了、結果画面の4地点で動作させてください。既存画面を圧迫する場合は会話パネルを開く方式にしてください。

## 9. 実装対象E：台本式チャット
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

見た目はチャット、内容は管理された台本式とします。自由文AIチャットやユーザー同士のチャットではありません。

- 左：NPCの仮アイコン、下の名前、吹き出し
- 右：自分のキャラクターの仮アイコン、吹き出し
- 返答は2～3個の選択肢
- 「あとで」「閉じる」を用意
- 閉じてもゲーム進行や学習記録を失わない
- 英語文は既存AudioServiceで読み上げ可能な構造
- 音声失敗でも進行可能
- `prefers-reduced-motion` ではタイピング演出を停止
- キーボード操作、フォーカス表示、ARIAを用意
- 320×568で横スクロール0

会話データは `src/data/dialogues/` に分離してください。

Phase 1-C1の台本は少量で構いません。最低限：

1. コース入口の挨拶
2. 日本へ出発または日本到着
3. ウェーブ終了の称賛
4. 結果画面の次回案内

NPC名はハードコードせず `speakerAvatarId` から解決してください。80人分の個別長文をこの工程で独断作成しないでください。共通テンプレートを使う場合も、後から個別台本へ差し替えられる構造にします。

## 14. 停止条件
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

以下の場合は変更せず停止してください。

- 正式リポジトリが異なる
- mainとorigin/mainが一致しない
- working treeがcleanでない
- 想定外のPhase 1実装が既にある
- 同名作業ブランチがあり、内容が不明
- 名前JSONが80件でない、または重複がある
- 既存テストが開始時点で失敗する
- 本番画像がないことを理由にコンセプトシートを切り抜く必要が生じる
- GitHub権限や認証に問題がある

停止時は、何も変更していないこと、確認値、必要な人間判断を報告してください。
