この文書の立場
--------------
いまの世界マップは CSS で描いた仮の表示（水色のグラデーションに白い楕円）で、
正式な地図イラストはまだ無い。この文書は、その正式なイラストを
ChatGPT 側で制作してもらうための表示条件をまとめたもの。

今回は調査と仕様づくりだけで、画像の制作も画面への差し替えも行っていない。
アプリのコードは1行も変更していない。
確定済みの色・光・地図配置・学習動作も変更していない。
正式サイト・main への反映は引き続き保留。

実測はすべて実ブラウザ（Chromium / Playwright・画素密度2倍）。
実測の基準は、採用済みの仮表示（Version 19 / b70021d、ユーザー実機確認で問題なし）。
ただし座標そのものは、正式画像ができてから取り直す（第3章 3-3）。

0. 制作前に決まったこと（2026-10-07）
────────────────────────────────────────────

  画像と枠
    ・制作キャンバスは 1536 x 1024、地図枠は 3 : 2
    ・画像の縦横を別々に伸ばさない
    ・画像と印は同じ座標基準（枠の幅・高さを 0〜1 とした割合）を使う
    ・正式画像を入れるときに、仮表示の白い楕円（.map__ocean）を外す
    ・ボタン・文字・ロック表示・チェック印・輪・引出線は画像に焼き込まない

  地理と座標
    ・仮座標に合わせて地形を変形させる方針は採らない
    ・西ヨーロッパから日本まで、海岸線と位置関係が自然に分かる地図にする
    ・装飾的なデフォルメは可。ただしロンドンとパリの距離・位置関係は
      大きく変えない
    ・輪は実際の地理の位置を示す。ボタンは必要に応じてずらし、引出線で結ぶ
    ・いまの -40px / +32px は必須条件ではない。正式画像に合わせて調整する
    ・正確な画素座標は、できあがった画像を見てから確定する

  縦長画面の余白
    ・地図・説明・同行者の帯・出発ボタンを、適度な間隔でひとまとまりにする
    ・出発ボタンだけを画面下端へ離し、上に大きな空白を残す配置は採らない
    ・背の高い画面では、このまとまりを見出しより下の領域で上下中央へ寄せる
    ・320x568 では画面内に収めることを優先し、文字や操作領域は縮めない
    ・高さが足りない場合はスクロールで到達できる構造にする

1-1. 地図枠（.map）

  画面サイズ    枠の幅    枠の高さ   縦横比    画面内の位置
  320x568     296.0    216.5    1.370    (12, 95.5)
  375x667     347.0    367.5    0.940    (14, 95.5)
  393x852     365.0    552.5    0.660    (14, 95.5)
  402x874     374.0    574.5    0.650    (14, 95.5)
  430x932     402.0    632.5    0.640    (14, 95.5)

  枠の幅  = 画面の幅 − 左右の余白（320px のときだけ 12px、ほかは 14px）
  枠の高さ = 画面の残り全部（flex: 1 1 auto）。だから画面ごとに大きく変わる。

  → 縦横比が 1.370 〜 0.640。いちばん横長の画面といちばん縦長の画面で
    2.14 倍ちがう。これが今回いちばん重要な数字。

1-2. 枠の角丸と切り取り

  角丸        border-radius: 18px（4隅とも）
  切り取り     overflow: hidden（枠からはみ出た描画は切られる）
  枠線        1px solid rgba(16, 36, 58, 0.16)
  いまの背景    linear-gradient(180deg, #bfe1f2, #96c9e6)
  白い楕円     .map__ocean（枠の 8%〜92%、border-radius 40% 55% 45% 50%）
              ※ 正式なイラストを入れる際は、この楕円は外す想定

  18px の角丸は、枠の幅に対して 4.5%（402px のとき）〜 6.1%（296px のとき）、
  高さに対して 6.7%〜9.1% にあたる。4隅のこの範囲は丸く切られる。

1-3. 日本・ロンドン・パリの位置

  座標は「枠の幅・高さを 0〜1 とした割合」。

  国        元の位置（指定値）    実際に印を描く位置

2. 画像の表示方式（決定と、その理由）
────────────────────────────────────────────

2-1. なぜ方式を決める必要があるのか

  枠の縦横比が 1.370 〜 0.640 まで変わる。
  1枚の画像で、この全部を「歪みなし・切れなし」で満たすことはできない。

  いまの方式のまま画像を枠いっぱいに敷くと：

    引き伸ばし（枠に合わせて縦横を別々に伸ばす）
      → 背の高い画面で地図が縦に 2 倍以上伸びる。国の形が崩れる。
        ご指示どおり、この方式は採らない。

    object-fit: cover（比を保ったまま枠を覆い、はみ出しを切る）
      → いちばん比の離れた画面では 53% が切れる。
        横に切れると、ロンドンか日本が画面から消える。

    object-fit: contain（比を保ったまま枠に収める）
      → 切れないが、枠の中に余白ができる。
        そして印は「枠に対する割合」で置いているので、
        画像の位置と印の位置がずれる。国の上に印が乗らなくなる。

2-2. 採用する方式（決定）

  ■ 地図枠の縦横比を固定し、画像を同じ比で作る（1 対 1 の対応にする）

    ・.map に縦横比を与え、高さを画面の残りで決めるのをやめる
    ・画像は枠とまったく同じ比なので、いっぱいに敷いても歪まない・切れない
    ・印は今のまま「枠に対する割合」で置ける
      → 画像の (u, v) と 印の (u, v) が常に同じ点を指す
      → 画面サイズが変わっても、国の位置と印は必ず一致する
    ・印の位置を決めるコードは変更不要（座標の指定はそのまま使える）

  ■ 採用する比：3 : 2（1.5）

    世界地図として自然な横長で、いちばん条件の厳しい 320x568 にも収まる。

      320x568 … 枠の幅 296 → 高さ 197.3（使える高さ 216.5 に 19.2 の余裕）
      375x667 … 347 → 231.3
      393x852 … 365 → 243.3
      402x874 … 374 → 249.3
      430x932 … 402 → 268.0

    実際にその場で CSS を足して5サイズを測った結果（アプリは未変更）
      印どうしの重なり   0 件
      枠からはみ出た印   0 件
      横スクロール      なし
      「出発する」ボタン  すべてのサイズで画面内に見えている

    ほかの候補も同じ条件で測り、いずれも問題なし。
      1.37（＝いまの 320x568 の比。320 では見た目がほぼ変わらない）
      1.6 （より横長。320 で地図の高さが 185px になる）

  ■ 保険として、画像には端から 4% の「捨て代」を見込む

    比を一致させれば切れないが、将来この画面の余白や文字の大きさが変わると
    枠の比が少し動く可能性がある。1.37〜1.6 の範囲で動いても
    切れるのは端から 4% までに収まる（計算：1.37/1.5 = 91.3%、1.5/1.6 = 93.8%）。
    大事なもの（国・都市・陸地の輪郭）は、端から 4% の内側に入れる。

2-3. 画面への影響（実装前に判断が必要なこと）

  比を固定すると、背の高い画面では地図が今より小さくなる。

    430x932 … 地図の高さ 632.5 → 268.0（364.5px ぶん小さくなる）
    393x852 … 552.5 → 243.3（309.2px）
    375x667 … 367.5 → 231.3（136.2px）
    320x568 … 216.5 → 197.3（19.2px）

  この余ったぶんを画面のどこへ回すかは、まだ決めていない。
  いまのまま比だけ変えると、同行者の帯と「出発する」ボタンの間に
  広い空白ができる（背の高い画面ほど目立つ）。

  考えられる扱い（いずれも未実施・次の工程での判断事項）
    ア 画面全体を上下の中央へ寄せ、余白を上下に分ける
    イ 地図と帯、帯とボタンの間隔を広げて余白を配る
    ウ 比を 4:3（1.333）寄りにして、余りを少し減らす
       （320x568 では 296/1.333 = 222 となり、使える高さ 216.5 を超えるため不可。
         つまり 320 を基準にすると 1.37 より横長にするしかない）

  → 比は 1.37 以上でなければ 320x568 に収まらない。
    1.5 を推奨するのは、1.37 ぎりぎりではなく少し余裕を持たせるため。

3. ChatGPT 側へ渡す制作仕様
────────────────────────────────────────────

3-1. 画像のサイズと形式

  キャンバス    1536 x 1024 px（3 : 2）
  形式        WebP（RGB・透過なし）
  目安の容量    300 〜 700 KB
              （既存の国紹介画像と同程度。japan-adopted.webp は 709x1536 で 406KB）
  画素数の根拠   表示される最大の幅は 402 CSS px。画素密度 3 の端末で 1206 px。
              1536 px あれば余裕がある。
              既存の採用画像（852 x 1847 = 1.57 メガ画素）と同じ画素数。

  焼き込まないもの（すべて DOM/CSS で重ねる）
    ・ボタン、国名の文字、ロック表示、チェック印
    ・引出線、元の位置を示す輪
    ・角丸、枠線、影、周囲のぼかし
      → 角丸 18px と 1px の枠線は CSS がかける。画像は四角いまま作る。

3-2. 表示する地理的範囲と向き

  向き        北が上。西が左、東が右（ふつうの向き）。
  入れる範囲    少なくとも 西ヨーロッパ 〜 日本 が横方向に収まること。
              海と陸がはっきり分かれていれば、投影法は問わない。
  下の 4 割    y 0.61 より下は、どの印も文字も乗らない。
              海や装飾を自由に置いてよい。

3-3. 地形と、日本・ロンドン・パリの位置（v2 で方針変更）

  ■ 取り消した方針（v1 の内容）

    v1 では「いまの仮座標（ロンドン 0.34/0.30、パリ 0.40/0.46、日本 0.78/0.44）に
    3点が来るよう、地形をデフォルメして描く」としていた。
    この方針は取り消す。仮座標ではロンドンとパリが縦に 0.16（164px）離れており、
    実際の緯度差 2.6 度とかけ離れているため、地図として不自然になる。

  ■ 新しい方針

    西ヨーロッパから日本まで、海岸線と位置関係が自然に理解できる地図にする。

      ・海岸線、大陸の形、島の並びは、見て国が分かる程度に自然であること
      ・装飾的なデフォルメ（丸み、簡略化、色づかい、絵本調の省略）は自由
      ・ただし、ロンドンとパリの距離や位置関係を大きく変えないこと
        （実際の 2 都市は近い。その近さが分かるように描く）
      ・日本は右端寄り、ヨーロッパは左寄り、という東西の関係を保つ

  ■ 座標の決め方

    印の座標は、できあがった画像を見てから取り直す。
    いまの仮座標（0.34/0.30、0.40/0.46、0.78/0.44）は、この段階では
    「おおよそこのあたり」という目安にすぎず、守る必要はない。

    画像を受け取ったあと、Claude 側で次の手順で確定する。
      1. 画像上のロンドン・パリ・東京の位置を、画素で読み取る
      2. 幅・高さを 0〜1 とした割合に直し、destinations.ts の position にする
      3. 印どうしが重ならないよう、必要な分だけ横（または縦）へずらし、
         ずれ量を displayOffset に入れる
      4. 5サイズで、重なり・はみ出し・横スクロールが無いことを測って確かめる

  ■ 印とボタンの関係（仕組みは据え置き）

    小さな輪（.map-anchor）… 実際の地理の位置を示す。ここが本当の場所。
    印のボタン            … 文字とロック表示を含むので大きい。
                           重ならないよう、必要に応じてずらして描く。
    引出線                … 輪とボタンを結ぶ短い線。

    いまの -40px / +32px は、仮表示で重なりを消すために決めた値であり、
    必須条件ではない。正式な画像に合わせて調整する前提。
    ずれが 0 で済むなら、輪と引出線は出さない（日本がいまそうなっている）。

  ■ 制作時に意識してほしいこと

    ロンドンとパリは実際に近いので、ボタン（64x59 と 46x59）を並べると
    かならず重なる。どちらかを横へずらして引出線で結ぶ形になる。
    そのため、2 都市の周囲（点から横に 0.25、縦に上下 0.15 ほど）は
    ボタンと文字で隠れる。下の 3-6 を参照。

3-4. 小さい画面でも必ず見える範囲

  枠の比と画像の比を一致させれば、画像の全体がどの画面でも見える（切れない）。

  そのうえで保険として
    必ず見える範囲   端から 4% の内側（x 0.04〜0.96 / y 0.04〜0.96）
                   画素では x 61〜1475 / y 41〜983
    大事なもの（陸地の輪郭、3つの都市、方角が分かる手がかり）は
    この内側に収める。

3-5. 切り取り可能な余白（捨て代）

  上下左右それぞれ 端から 4%（上下 41px、左右 61px）。
  ここには海や空だけを置き、陸地や都市を置かない。

  加えて 4隅は角丸で丸く切られる。
    幅の 6.1% x 高さの 9.1%（画素で 94 x 93）の四角い範囲が隅ごとに欠ける。
    4隅には大事なものを置かない。

3-6. 印や文字が重なるため、描き込みを控える場所（v2 で書き直し）

  座標を画像から取り直すので、v1 のような決め打ちの箱では指定できない。
  かわりに「都市の点を中心に、どれだけの範囲が隠れるか」で示す。

  ■ 都市の点1つあたり、隠れる範囲の目安（幅・高さを 0〜1 とした値）

    縦    点から 上へ 0.15、下へ 0.15（合わせて 0.30）
          キャンバス 1024px では、点の上下それぞれ 154px
    横    ずらさない都市（日本のような、国名だけのもの）
            点から 左右それぞれ 0.075（キャンバスで 115px）
          ずらす都市（ロンドン・パリのような、ロック表示もあるもの）
            引出線の向きへ 最大 0.25（384px）、反対側へ 0.05（77px）

  ■ 根拠（比 1.5 に固定したときの実測。印の箱の大きさは px で固定）

    印の箱      日本 44x44 / ロンドン 64x59 / パリ 46x59
    枠の大きさ   296x197.3（320x568）〜 402x268.0（430x932）
    → 箱の高さは枠の高さの 0.220（大きい画面）〜 0.299（小さい画面）
      箱の幅は枠の幅の 0.109〜0.216
      いちばん不利な 320x568 の値を採って、上の目安にしている。

  ■ いまの仮座標での具体値（参考。座標が変われば変わる）

    ロンドンの印一式   x 0.100〜0.320 / y 0.150〜0.450
    パリの印一式      x 0.420〜0.590 / y 0.310〜0.610
    日本の印一式      x 0.700〜0.850 / y 0.330〜0.550

  ■ この範囲で避けてほしいこと

    ・細かい模様、文字、地名の描き込み
    ・濃い色と明るい色が隣り合う強い明暗差
    ・真っ白や真っ黒（淡い青ガラスのボタンは背後が 14% 透けるため、
      濃紺の文字が読みにくくなる）

    中間の明るさの海・空の色にしておくと、どの都市に印が来ても困らない。
    3 都市は横一列に近い帯（キャンバスの上から 3〜6 割あたり）に入る見込みなので、
    その帯は全体として落ち着いた面にしておくと安全。

3-7. 色の合わせ先（いまの画面の色）

  いまの枠の背景   上 #bfe1f2 → 下 #96c9e6（水色のグラデーション）
  画面の地色      #fdf8ee 寄りの温かい白
  ボタンの青      濃い面 rgb(35, 77, 231) / 淡い面 rgb(154, 203, 253)
  文字の濃紺      #0b2d4f

  画像の上下端は、枠の背景色に近い色で終わらせると、
  万一の切れや余白が目立ちにくい。


────────────────────────────────────────────
4. 縦長画面の余白配分（レイアウト案・v2 で追加）
────────────────────────────────────────────

4-1. 直したいこと

  地図枠の比を 3:2 に固定すると、背の高い画面では地図が今より小さくなり、
  余りが出る。いまの作りのままだと、その余りが
  「同行者の帯」と「出発する」の間にそのまま空白として残る。
  （.screen__footer の margin-top: auto が、ボタンを画面の下端へ押しやるため）

  この配置は採用しない。
  地図・説明・同行者の帯・出発ボタンを、適度な間隔でひとまとまりにする。

4-2. 案

  ・地図は 3:2 に固定する
  ・「出発する」を下端へ押しやる margin-top: auto をやめる
  ・まとまり全体を、見出しより下の使える領域で上下中央へ寄せる
  ・要素どうしの間隔は 14px（いまは 10px）
  ・入りきらない画面では、スクロールで下まで到達できるようにする

  上下中央へ寄せる方法は、まとまりの先頭に margin-top: auto、
  末尾に margin-bottom: auto を置く形にする。
  余りが無いときは auto が 0 になるので、中身の上が切れて
  たどり着けなくなることがない（justify-content: center だとその恐れがある）。

  当てる指定のかたち（案。まだ実装していない）

    .screen--map .map {
      flex: 0 0 auto; aspect-ratio: 3 / 2; height: auto;
      margin-top: auto;          /* 上の余りを作る */
    }
    .screen--map .screen__body {
      overflow-y: auto;          /* 入りきらない画面はスクロールで届く */
      gap: 14px;
    }
    .screen--map .screen__footer {
      margin-top: 0;             /* 下端へ押しやるのをやめる */
      margin-bottom: auto;       /* 下の余りを作る */
    }

  ※ .screen__body には「光の逃げ場」の余白が既にあるので、
    overflow-y を足してもボタンの外周の光は切られない。
