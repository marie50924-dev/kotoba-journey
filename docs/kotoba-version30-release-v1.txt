4. 確認版のビルドが、正式公開用ビルドと違う点
---------------------------------------------
確認版は配信先のパスに合わせて base を './' にしている。Version 29 までと同じ。
今回はこれに加えて、確認版の作業コピーだけで素材URLの書き方を直した
（リポジトリには入れていない。アプリの中身・デザイン・素材は同じ）。

  理由：v23 の受領物は素材URLを "/kotoba-journey/assets/avatars/reference-v23/…"
  と絶対パスで書いている。正式公開先（GitHub Pages の /kotoba-journey/）では
  これで解決するが、確認版の配信先は別のパスなので解決できない。

  直した箇所（確認版の作業コピーのみ）
    src/styles/reference-v23-card.css   url の先頭 "/kotoba-journey/" → "/"
        ビルド後は Vite が base を当てて "../assets/avatars/reference-v23/…" になる。
    src/components/attachReferenceV23.ts  胴体のURLを
        `${import.meta.env.BASE_URL}assets/avatars/reference-v23/body-f.png` にした。
        アプリの他の素材と同じ書き方。

  配信物で、参照される素材7枚すべてが 200 で取得できることを確認した。
    body-f.png / body-mask.png / head-blend.png / center-f-mask.png /
    rim-f-mask.png / frost-f-mask.png / footprint-f-mask.png
  CSS に残る m 用の4枚（center-m / rim-m / frost-m / footprint-m）は、
  七海が f のため選択子が当たらず、取得そのものが発生しない。

以前の報告の訂正
  fit-v3 の比較報告で「赤いリボンの見える下端が 96.8%/96.4% へ伸びた」「画素数が
  +53%/+36%」と書いたのは、ゆるい判定（R-max(G,B)>=60）による値で、
  明るい茶色の髪のつやも拾っていた。同じ報告で厳しい判定の 6〜12点を
  「数としては当てになりません」と書いたが、これは誤り。
