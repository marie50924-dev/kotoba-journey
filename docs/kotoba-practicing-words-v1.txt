1. 採用し、維持する内容
-----------------------
保存と更新ルール
  区分は「そのことばが最後に出たプレイの結果」だけで決まる。
    誤答0回    → まちがいなし（masteredPairIds）
    誤答1回    → 練習中      （practicingPairIds）
    誤答2回以上 → 復習        （reviewPairIds）
  今回出たことばは3つすべてからいったん外してから入れ直すので、
  同じことばが2つ以上の区分へ同時に入ることはない。
  今回出題されなかったことばには触れないため、その記録はそのまま残る。
  誤答回数はどこにも保存しないので、過去のプレイとは足し合わせない。

保存形式
  保存キー kotoba-journey/learning-record/v1 … 変更なし
  世代番号 RECORD_VERSION = 3                … 変更なし
  practicingPairIds を1項目だけ追加。
  この項目が無い古い保存データは空の配列として読む（後方互換）。
  過去の練習中のことばは保存されていなかったので、推測で補わない。
  既存の利用者の記録は削除していない。

表示
  数値タイルは6枚のまま。
  「練習中のことば」を「復習することば」の上に置く。
  両方の見出しに語数を出す（例「練習中のことば（2語）」）。
  空のときは「該当することばはありません」。
  記録そのものが無いことを指す「まだ記録がありません」とは言い分ける。
  どちらの一覧も先頭10語を出し、11語以上なら
  「すべて見る（○語）」で開き「折りたたむ」で戻す。
  一覧の中だけをスクロールさせる作りは使わない。
  開閉は普通のボタンとパネルで作るので、キーボードでも操作でき、
  aria-expanded で開閉の状態を読み上げへ伝える。

文言
  数値タイルの補足 「記録上、まちがいなしに分類されていることばの数」
  練習中の説明     「そのことばが最後に出たプレイで、1回まちがえたことば」
  復習の説明       「そのことばが最後に出たプレイで、2回以上まちがえたことば」
  区分の説明       「ことばの区分は、今回から、そのことばが最後に出たプレイの
                    結果で更新します。以前の記録は引き継ぎ、過去の練習中の
                    ことばは復元しません。」
  旧記録を含む全件が新ルールで分類し直されている、とは書いていない。

追加の変更は不要との指示を受けている。以上をこのまま維持する。

4. 検査用スクリプトの修正（2026-10-08 に訂正）
-----------------------------------------------
ボタンの外側の光が親要素で切り取られていないかを調べる検査器を、
2度にわたって直した。アプリのコードの問題ではない。

4-1. 最初の誤り
  画面の外にあってスクロールが必要なだけのボタンを、
  「光が切り取られている」と数えていた。
  マイパスポートの「設定」について 320x568 で「余裕 -407.5px」と出ていたが、
  これは画面外にあることを表していただけだった。

4-2. 1度目の修正の誤り（これも誤り。ここで訂正する）
  このとき「overflow が auto / scroll の親は切り取らずスクロールして
  見せるだけなので数えない」と書き、検査の対象から外した。
  **これは誤りである。auto / scroll も表示領域の縁で描画を切り取る。**
  スクロールで動くのは中身の位置であって、箱の外へ出た光は切られる。
  一律に除外してはいけない。

4-3. 現在の判定（作り直した版）
  (ア) まず対象を画面内へ送る（scrollIntoView）。
       画面外にあるだけなのか、送っても光が収まらないのかを分けるため。
  (イ) 送ったあとの位置で、切り取る祖先ごとに余裕を測る。
  (ウ) 切り取る祖先 = **計算済みの** overflow-x / overflow-y が visible 以外。
       hidden・clip・auto・scroll をすべて対象にする。
       指定値では判断しない。片方が hidden のとき、もう片方に visible を
       指定しても計算済みの値は auto になるため。
  (エ) 切り取りの境界はパディングボックス。枠線の太さを差し引いて測る。
  (オ) 根元のスクロール要素だけは、切り取りの境界が表示領域そのものなので、
       祖先の箱ではなく表示領域の縁で測る。
  (カ) 通常時とフォーカス時の両方で測る。

  判定は3つに分ける。
      スクロールしても画面に入らない
      光が切れている（送っても光が箱に収まらない）
      光まで収まっている

4-4. 光が外へ届く距離（base.css の --glass-glow を読んだ値）
      上 8px   0 0 8px の光
      下 13px  0 4px 9px の影（下へ 4+9）
      左右 9px 0 4px 9px の影のぼかし
  工程で使ってきた安全側の基準は 11px、余白 --glow-room は 12px。
  フォーカス時に足される輪郭（outline 3px / offset 2px＝5px）と
  0 0 0 6px の輪（6px）は、いずれも上の距離より内側に収まる。

4-5. 検査器そのものの試験
  見分けられることを、作った3つの場面で確かめた。
      (a) 余白のあるスクロール箱の中のボタン
          → 送れば光まで見える       → 「光まで収まっている」
      (b) 余白のないスクロール箱の、いちばん下のボタン
          → ボタンには届くが光が切れる → 「光が切れている」
      (c) overflow-x: hidden の箱の、左端に寄せたボタン
          → 横の光が切れる             → 「光が切れている」
  (c) では、overflow-y に visible を指定しても計算済みの値が auto になることも
  あわせて確認した。3件とも期待どおりで、自己試験は合格。

4-6. 作り直した検査器での再測定（マイパスポート・対応5サイズ）
  練習中53語・復習52語を仕込み、両方の一覧を開いた状態で、
  画面にあるボタンすべて（もどる／折りたたむ×2／設定）を測った。

  **アプリ側の見切れは見つからなかった。** 5サイズとも、通常時・フォーカス時の
  どちらも「光まで収まっている」。いちばん狭い余裕は次のとおり。

      もどる  上 12px ／ 左 12px（320x568。他のサイズは左 14px）
      設定    下 24px ／ 左 12px
      折りたたむ  左 12px ／ 上下は 213px 以上

  いずれも、いちばん外へ届く距離（上 8 / 下 13 / 左右 9）と、
  安全側の基準 11px の、どちらも上回っている。
  切り取る祖先は .screen__body（overflow auto）、その親の div、
  body、html で、すべてを対象に数えたうえでの結果。

  前回の報告に載せた「光の見切れ 0件」という結論は変わらないが、
  その根拠だった判定方法は誤っていた。上の方法で測り直した値に差し替える。
