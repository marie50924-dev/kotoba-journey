# スマートフォンで確認するための起動手順

パソコンの中だけで動かしているアプリを、手元のスマートフォンで開いて確かめるための手順です。
インターネットには公開しません。**同じWi-Fi（同じLAN）の中からだけ**開けます。

---

## 0. 用意するもの

- パソコンとスマートフォンが **同じWi-Fiにつながっている**こと
  （スマホの「モバイル通信」ではなく、パソコンと同じWi-Fiに切り替えてください）
- パソコンに Node.js（v20 以上）が入っていること
- このリポジトリのチェックアウト

---

## 1. いちばん短い手順（3行）

```bash
npm ci
npm run build
npm run serve:phone
```

最後の行を実行すると、こういう表示が出ます。

```
  ことばトラベル／スマートフォン確認用サーバー
  配っているもの: dist/   方式: http

  このパソコンで開く
    http://localhost:5180/kotoba-journey/

  同じWi-Fiのスマホから開く（スマホのブラウザにこのまま入力）
    http://192.168.1.23:5180/kotoba-journey/   （en0）

  終わるときは Ctrl+C
```

**「同じWi-Fiのスマホから開く」に出たアドレスを、スマホのブラウザにそのまま入力**してください。
`192.168.1.23` の部分はパソコンごとに変わります。表示されたものを使ってください。

末尾の `/kotoba-journey/` を打ち忘れても、入口へ自動で移ります。
`http://192.168.1.23:5180` だけでも開けます。

終わるときは、実行したターミナルで **Ctrl+C**。

---

## 2. アドレスの読み方

| 部分 | 意味 |
|---|---|
| `http://` | 方式。`npm run serve:phone:https` を使うと `https://` になります |
| `192.168.1.23` | パソコンのWi-Fi上の番号。**毎回同じとは限りません**。起動のたびに表示を見てください |
| `:5180` | ポート。ふさがっていたら `--port` で変えられます |
| `/kotoba-journey/` | アプリの入口。`vite.config.ts` の `base` と同じです |

---

## 3. 直しながら確認したいとき（自動で作り直す）

コードを直すたびに `npm run build` をやり直すのが面倒なときは、開発サーバーを使います。

```bash
npm run dev:phone
```

表示された `Network:` の行のアドレスを、スマホのブラウザに入力してください。
ファイルを保存すると、スマホの画面も自動で入れ替わります。

- `npm run serve:phone` … ビルドしたもの（本番に近い状態）を配る。**見た目と動きの確認向き**
- `npm run dev:phone` … 直したそばから反映する。**作りながらの確認向き**

## 4. https で開きたいとき

```bash
npm run serve:phone:https
```

自己署名の証明書をその場で作って（`.cert/` に置きます）、`https://` で配ります。

スマホで開くと「この接続ではプライバシーが保護されません」「安全ではありません」と出ます。
これは自分で作った証明書だからです。**詳細／詳しく → このまま進む**を選んでください。

- iPhone（Safari）: 「詳細を表示」→「このWebサイトを閲覧」
- Android（Chrome）: 「詳細設定」→「<アドレス> にアクセスする（安全ではありません）」

`.cert/` は git の追跡対象外にしてあります。消しても次回また作られます。

> **なぜ https を用意しているか**
> ブラウザによっては、保護された接続（https）のときだけ使える機能があります。
> まず `npm run serve:phone`（http）で試し、スマホで動かない機能があったときに
> `npm run serve:phone:https` を試す、という順番で十分です。
> どちらが必要かは**実機で確かめてください**（この手順書を書いた時点では実機未確認です）。

## 6. スマホで試すと良いところ

通して遊ぶより先に、短い確認から始められます。

1. **「まず3ペアで試す」**
   表紙 →「旅をはじめる」→ 人物を選ぶ → コース入口 → **「まず3ペアで試す」**
   りんご・ねこ・いぬの6枚だけ。3語とも単語イラストが出ます。
   学習記録には残らないので、何度試しても記録が汚れません。

2. **指でのスライド**
   札を指で持ち上げて、対応する札に重ねて離す。
   タップ（1枚えらぶ → 相手をタップ）でも同じように答えられます。

3. **音と振動**
   カルタ画面の右上「音設定」で、**発音**と**効果音**を別々に切り替えられます。
   - 正解 … 短い明るい音＋金色の光
   - 不正解 … 短い控えめな音＋赤い縁＋**短い振動**
   iPhone はブラウザからの振動に対応していないことがあります。
   鳴らない・震えない場合も、ゲームは止まりません。

4. **通して遊ぶ**
   コース入口 → 分類を選ぶ → コース → 枚数 → 出発 → カルタ → 結果 → マイパスポート

## 7. うまくいかないとき

| 症状 | 見るところ |
|---|---|
| スマホでページが出ない | スマホが**モバイル通信**になっていないか。パソコンと同じWi-Fiか |
| つながらないまま待たされる | パソコンのファイアウォールがそのポートを止めていないか。`--port` を変えて試す |
| 「ポートはすでに使われています」 | 別のポートで起動する（`--port 5181` など） |
| `dist/index.html が見つかりません` | 先に `npm ci && npm run build` |
| 画面が白いまま | アドレスの末尾が `/kotoba-journey/` になっているか（省略しても自動で移ります） |
| 直したのに古いままに見える | スマホで再読み込み。配信側はキャッシュしない設定（`Cache-Control: no-store`）です |
| 会社や学校のWi-Fi | 端末どうしの通信が禁止されていることがあります。家庭のWi-Fiやテザリングで試してください |

---

## 8. この手順で確認していること・していないこと

**確認できていること**（Chromium からLANアドレスで接続して実測）

- `http://<パソコンのアドレス>:5180/kotoba-journey/` で、表紙から体験の正解表示・音設定まで動く
- `https://` でも同じように動く（自己署名の証明書）
- 末尾を省いたアドレスでも入口へ移る
- 画像・スタイル・スクリプト・単語イラスト・顔画像がすべて読み込める（404 なし、JS例外なし）

**確認できていないこと**

- **実機（iPhone / Android）での表示・操作感・音量・振動は未確認です。**
  この手順書は、同じ仕組みに Chromium からLANアドレスで接続して確かめたものです。
- 公開環境・Safari実機は未確認です。公開はしていません。
