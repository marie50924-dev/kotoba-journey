# ことばトラベル / KOTOBA JOURNEY

日本語カードと英語カードを同じ盤面へ混ぜたカルタで遊びながら、
ことばを覚えて世界をめぐる学習ゲームです。

> **現在はグレーボックス工程（Phase 0）です。**
> 正式なイラスト・正式な音声・課金機能はまだ実装していません。
> いまの目的は「表紙 → コース選択 → 枚数選択 → 世界マップ → カルタ →
> 正解時の発音確認 → 結果・分析 → マイパスポート」までを
> スマートフォン上で実際に操作できる状態にすることです。
> 画面の見た目は CSS による仮表示で、後工程ですべて差し替えます。

このゲームは他タイトルとは独立した新規作品です。他リポジトリのコード・画像・
音声・設定は一切流用していません。

---

## ゲームの流れ

1. **表紙** — 「旅をはじめる」から出発します。
2. **コース入口** — 学年別 / 資格・試験 / 社会人 の3分類。
3. **コース選択** — 学年（小〜大学生）、英検8段階、TOEIC目標6段階、社会人6分野。
   資格名やロゴを模した画像は作らず、文字だけで選びます。
4. **枚数選択** — 6枚（3ペア・やさしい）/ 12枚（6ペア・ふつう）/ 20枚（10ペア・むずかしい）。
5. **世界マップ** — 現在は日本のみ選択可能。ロンドンとパリはロック表示です。
6. **カルタ** — 日本語カードと英語カードが混在した盤面からペアを探します。
7. **発音確認** — 正解するたびに中央の小さなパネルで日本語・英語・発音を確認します。
8. **結果・分析** — 正解率、クリア時間、自己ベスト、習得状況、間違えた単語。
9. **マイパスポート** — 端末に残した学習記録の一覧。

### カルタのルール

1. カードを1枚選ぶと選択状態になります。
2. 2枚目が**同じ言語**なら不成立として選択を解除します（不正解には数えません）。
3. 日本語と英語で `pairId` が一致すれば正解。異なれば不正解です。
4. 正解したカードは盤面から消さず、発音確認を見せてから取得済み表示にします。
5. 不正解のカードは短時間表示してから元に戻します。
6. 判定中は入力をロックし、連打を防ぎます。
7. 全ペアを取得すると結果画面へ進みます。

記録している値：正解ペア数、不正解回数、経過時間、pairId ごとの誤答回数、
pairId ごとの回答時間。

### カード配置について

「本物のカルタを広げたような見た目」を、安全に成立させるため
**自由配置ではなくスロット方式**で計算しています（`src/domain/layout.ts`）。

- 枚数ごとに列×行を固定（6枚=2×3、12枚=3×4、20枚=4×5）
- 各カードは自分のセルの内側に収める
- **傾けた後の外接矩形**もセルに収まるサイズを逆算する
- そのうえで傾きだけを小さな範囲でランダムに変える

この方法により、カード同士は原理的に重なりません。全カードの四辺が盤面内に
収まること・タップ領域が確保されることは、対象5サイズ × 3枚数の全組み合わせで
自動テストしています。カード順は毎回変わり、20枚でも一画面に収まります。
320×568 では傾きと装飾を減らし、盤面の読みやすさを優先します。

### 正解率の計算式

```
正解率(%) = correctSelections / (correctSelections + incorrectSelections) × 100
```

- `correctSelections` … 日英ペアが一致した回数
- `incorrectSelections` … 日英だが `pairId` が異なった回数
- 同じ言語同士の不成立は**どちらにも数えません**
- 分母が 0 の場合は 0 を返し、0除算を防いでいます
- 小数第1位で丸めます

実装は `src/domain/scoring.ts` の `calculateAccuracy()` です。

### 習得判定（仮仕様）

| 1プレイ中の誤答回数 | 判定 |
| --- | --- |
| 0回 | 習得 |
| 1回 | 練習中 |
| 2回以上 | 復習 |

これは Phase 0 の仮仕様です。正式な習得判定は後工程で確定します。

## 技術構成

| 項目 | 採用 |
| --- | --- |
| ビルド | Vite |
| 言語 | TypeScript |
| UI | HTML / CSS / DOM 直接操作 |
| テスト | Vitest（単体）/ Playwright（表示回帰） |
| 保存 | localStorage |
| 公開 | GitHub Pages（GitHub Actions） |

**採用していないもの：** Phaser、React / Vue などの UI フレームワーク、CDN 依存、
サーバー必須構成、外部広告 SDK、外部分析 SDK、課金機能、ログイン機能。

カード選択型 UI のため、ゲームエンジンではなく通常の DOM / CSS を使っています。
将来 Capacitor で iOS アプリ化できるよう、静的ファイルだけで完結する構成です。

### ディレクトリ構成

```
src/
  app/        ルーター・アプリ状態・DOMヘルパー
  screens/    画面ごとの描画
  components/ 画面共通の部品（外枠、発音確認パネル）
  data/       コース定義・仮単語データ・UI文字列
  domain/     ルールと計算（デッキ、シャッフル、判定、集計、配置）
  services/   音声・課金の境界
  storage/    localStorage の読み書きと復旧
  styles/     CSS
  tests/      Vitest のテスト
```

**表示・ルール・保存・音声を分離**しています。`domain/` は DOM に一切触れず、
UI 文字列は `data/strings.ts` に集約してロジック側へ散在させていません。

## 開発コマンド

```bash
npm install     # 依存パッケージの取得
npm run dev     # 開発サーバー
npm test        # テスト（Vitest）
npm run build   # 型チェック + 本番ビルド（dist/ へ出力）
npm run preview # ビルド結果の確認
```

### テスト方法

```bash
npm test           # 単体テスト 1回実行（Vitest 133件）
npm run test:watch # 変更を監視して実行
npm run test:visual # 表示回帰テスト（要 npm run build。実ブラウザで描画して検証）
```

自動テストの対象：

- 3 / 6 / 10 ペアのデッキ生成、日英同数、`pairId` の1対1対応
- seed 付きシャッフルの再現性（同じ seed で同じ並び）
- 同一言語同士の不成立、正しい日英ペアの正解、異なる `pairId` の不正解
- 入力ロック、全ペア取得時のクリア判定
- 正解率の計算（0除算を含む）と習得状態の判定
- 対象5サイズ × 6/12/20枚の配置スロットが重ならず画面内に収まること
- localStorage への保存・復旧、壊れた保存データからの復旧
- コース選択・音声設定の保存
- 音声非対応時にもゲームを進行できること

`npm run test:visual` は、CSS レイアウトの結果でしか確認できない項目を
実ブラウザ（Chromium）で描画して検証します。ビルド済みの `dist/` を対象にするため、
先に `npm run build` を実行してください。対象5サイズすべてで、発音確認パネルの
2ボタンについて次を確認します。

- 「もういちど聞く」「つぎへ」がパネル内に収まる
- 両ボタンの外接矩形が重ならない
- 両ボタンの `scrollWidth <= clientWidth`
- パネルに横方向の overflow がない
- 文言が省略や折り返しなく1行で全文表示される
- タップ領域が 44 × 44 CSS px 以上
- 背景カードへの入力ロックが効いている

### ビルド方法

```bash
npm run build
```

`tsc --noEmit` による型チェックのあと、`dist/` へ静的ファイルを出力します。

## GitHub Pages 構成

- Vite の `base` を `/kotoba-journey/` に設定しています（`vite.config.ts`）。
- 想定公開パス： `https://<owner>.github.io/kotoba-journey/`
- `.github/workflows/deploy.yml` が `main` への push で
  テスト → ビルド → Pages へのデプロイを実行します。
- `.github/workflows/ci.yml` はそれ以外のブランチと Pull Request で
  テストとビルドだけを実行します。

> **Pages の有効化はリポジトリ設定が必要です。**
> リポジトリの Settings → Pages で **Source を「GitHub Actions」** に
> 変更してください。この設定は Actions 側からは変更できません。

## 対象画面サイズ

スマートフォン縦画面を基準にしています。

| サイズ | 想定端末 |
| --- | --- |
| 320 × 568 | 小型端末（最小構成） |
| 375 × 667 | iPhone SE 系 |
| 393 × 852 | iPhone 15 系 |
| 402 × 874 | iPhone 16 系 |
| 430 × 932 | iPhone Pro Max 系 |

満たしている条件：

- 横スクロールを発生させない
- 主要ボタンが画面外へ出ない
- `safe-area-inset` を考慮（`viewport-fit=cover`）
- 文字を画像へ焼き込まない（すべてテキスト描画）
- 320 × 568 でも操作できる
- 20枚のカルタも一画面内に表示し、カルタ画面は縦スクロールさせない

## 発音について

**今回、音声ファイルは新規生成していません。** 仮実装として、Web Speech API
(`SpeechSynthesis`) が利用できる端末でのみ英単語を英語音声で読み上げます。

- `SpeechSynthesis` の対応判定を行います
- 非対応でもゲーム進行は止まりません
- 音声が失敗しても「つぎへ」は必ず押せます
- 自動再生がブロックされる端末に備え、「もういちど聞く」ボタンを用意しています
- 将来、正式な音声ファイルへ差し替えられるよう `AudioService`
  （`src/services/audioService.ts`）をインターフェースとして切り出しています
- テストはブラウザの音声機能に依存しません（差し替え可能な実装でテストします）

## 学習記録とプライバシー

学習記録は**現在 localStorage にのみ保存**しています。サーバーへは送信しません。

保存している内容：

- 総プレイ回数、学習した日付の一覧、連続学習日数（日付から計算）
- 通算の正解数・不正解数、通算正解率
- 覚えた単語（習得した `pairId`）、復習対象の `pairId`
- 枚数ごとのベストタイム、選択中コース、訪れた国
- 最近のプレイ履歴（最大10件）、音声 ON / OFF 設定

**保存しないもの：子どもの個人情報（名前・年齢・学校名・メールアドレス等）を
一切収集・保存しません。** ログイン機能もありません。

保存データが壊れていても起動不能にならないよう、安全なパースと初期値復旧を
実装しています（`src/storage/learningRecord.ts`）。`localStorage` が使えない
環境ではメモリ上の代替へ自動的に切り替わります。

設定画面から「学習記録を消去」（確認ダイアログを経由）と
「音声 ON / OFF」を操作できます。
